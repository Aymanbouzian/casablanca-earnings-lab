# Put the project in front of a reviewer

## Before publishing

Run the demo and read `README.md`, `docs/case_study.md` and
`docs/interview_guide.md`. Be able to explain one rejected forecast and one
cash-accounting example in your own words. Edit application wording to match
what you have personally reviewed or implemented.

## GitHub presentation

Use a separate repository named **casablanca-earnings-lab**. Upload the contents
of this project folder so `README.md`, `run_demo.py`, `tests/` and `.github/`
are at the repository root. Keep the included `.gitignore`.

Suggested description:

> Python earnings-event research for Casablanca equities: dated forecasts,
> explicit exclusions, trading costs, portfolio accounting and a synthetic demo.

Use the topics in `docs/career_assets.md`. Check the first Actions run, inspect
the README rendering, and then pin the repository on your GitHub profile.
The archive is prepared for publication; it does not imply that a remote
repository has already been created or that CI has run.

## CV and professional profile

Add one project entry linking directly to the repository. Use the research or
Python wording in `docs/career_assets.md`, according to the role. Attach the
case study or a short demo walkthrough to your professional profile's featured
projects area if available.

## A 90-second walkthrough

1. State the question in ordinary language: does unexpected profit predict
   a useful return after costs?
2. Show the event-audit row where a newer forecast removes a supposed surprise.
3. Show a test for future-information leakage or cash accounting.
4. Open the demo ledger and explain an exit that could not fill immediately.
5. Finish with the actual result and the next data improvement.

Then make one evidence-backed improvement yourself and keep its real commit.
Target relevant internships or junior roles and include the project link in
the application. The files contain draft wording only; no applications or
messages have been sent.
